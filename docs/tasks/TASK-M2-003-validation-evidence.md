## Exact Limits

Validation confirmed:

- upload sizes at 1 MiB minus 1, exactly 1 MiB, and 1 MiB plus 1;
- 99, 100, and 101 columns;
- 9,999, 10,000, and 10,001 data rows;
- 16 KiB minus 1, exactly 16 KiB, and 16 KiB plus 1 cell content;
- multibyte UTF-8 cell content at and over the 16 KiB byte boundary.

Oversized inputs fail without truncation.

## UTF-8 And BOM

Validation covered ASCII UTF-8, multibyte UTF-8, UTF-8 with BOM, invalid
UTF-8, and a truncated multibyte sequence. Decoding does not replace invalid
bytes. BOM is stripped before CSV parsing, while SHA-256 is calculated over
the original uploaded bytes including BOM.

## CSV Parsing

Validation confirmed use of CSV parser semantics:

- quoted commas are accepted;
- quoted embedded newlines count as one logical data row;
- escaped quotes are accepted;
- CRLF and LF rows are accepted;
- unclosed quotes fail boundedly;
- inconsistent row width fails as malformed CSV;
- empty body and header-only dataset fail as empty dataset.

No type inference or `DatasetProfile` generation occurs.

## Header And Column Semantics

Header rows are required and excluded from data-row counts. Duplicate column
comparison is exact and case-sensitive; `Name` and `name` are distinct. The
implementation does not invent whitespace trimming or case folding beyond the
frozen requirements.

## Filename And Path Audit

Validation covered ordinary filenames, Unicode filenames, NFC normalization,
exactly 128 characters, 129 characters, empty names, NUL, controls, `/`, `\`,
`.`, `..`, POSIX absolute paths, Windows drive-qualified paths, UNC-like
forms, and mixed traversal forms.

Two uploads with different valid client filenames were staged under generated
artifact-derived names. The client filename was not present in the staged
locator and did not create a path, directory, open target, or cleanup target.

## Staging Locator And Containment

Validation confirmed the staged locator is generated by the intake boundary,
bounded, opaque, provider-neutral, and derived from the server-selected
`ArtifactId`. Malformed and foreign locator strings fail boundedly.

Containment probes verified:

- staged reads return exact original bytes;
- invalid locators cannot read external files;
- invalid cleanup cannot delete an outside sibling file;
- cleanup of one staged dataset does not affect another;
- an existing generated-path symlink to an outside file is rejected before
  writing through it.

## Cleanup And Replay

Cleanup removes the intended staged object and is idempotent for the same
generated locator. After cleanup, `ArtifactReference` metadata remains
recorded metadata, but staged reads fail with `DATALAB_DATASET_UNAVAILABLE`.
No hidden cache or recreation path was found. Re-analysis requires a new
upload.

The current local staging store can read still-present staged bytes after the
store object is recreated, which matches the frozen ephemeral staging model:
restart recovery is not claimed as durable persistence, and availability is
still proven by locator plus bytes plus SHA-256.

## SHA And ArtifactReference

Known byte fixtures were hashed independently and matched the generated
`IntegrityDescriptor(algorithm=sha256)`. Different bytes produce different
digests. Client filename metadata does not affect the content digest.

Produced dataset references have:

- `kind=dataset`;
- `media_type=text/csv`;
- canonical SHA-256 integrity;
- producer/provenance as `ObjectReference`;
- bounded generated locator;
- no embedded raw bytes.

No `DatasetReference` or duplicate dataset/hash abstraction exists.

## Safe Errors

Inputs containing credential-like text, filesystem paths, CSV cell values,
unsafe filenames, and malformed quoted content were rejected without echoing
raw input, server paths, staged locators, parser diagnostics, tracebacks, or
provider/framework details through the public error message or JSON-compatible
error representation.

## Determinism And Boundedness

Equivalent bytes and equivalent normalized filename metadata produce the same
validation outcome, CSV shape interpretation, and SHA-256 digest. Artifact IDs
and staged locators are intentionally generated or caller-supplied test
fixtures and are not content-deterministic.

The implementation bounds upload size before decoding/parsing/staging, streams
CSV rows through the parser without retaining the full row set, stops on
over-bound inputs, and contains no recursive, polling, retry, scheduler, or
network behavior.

## Authority Audit

Authorized implementation authority is limited to supplied bytes, UTF-8
decoding, standard-library CSV parsing, SHA-256 calculation, bounded local
staging, staged read, cleanup, and canonical artifact construction.

Validation confirmed absence of:

- network or remote URL fetch;
- provider/model SDK invocation;
- subprocess or shell execution;
- plugin or dynamic import execution;
- database writes or persistence schema;
- API routes or web/UI behavior;
- scheduler or autonomous loop.
